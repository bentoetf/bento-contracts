# Risks / Limitations

- **Unaudited prototype.** Contracts need experienced Solidity review and ideally formal audit before value.
- **RPC/fork reliability.** `https://rpc.mainnet.chain.robinhood.com` answers basic JSON-RPC, but direct Foundry fork requests were challenged by Cloudflare from this Mac. The live fork report used the included local header-setting proxy (`scripts/rh_rpc_proxy.py`) to reach the same upstream RPC.
- **V4 adapter integration.** `BoxEngine` supports legacy V2 routes and adapter sentinel routes (`path[0] == address(0)`). Adapter-routed components must have a stock/USD feed and the engine must have ETH/USD configured so sanity/NAV math cannot silently fall back to zero.
- **Per-component slippage minima must be populated by frontends.** `mint` and `redeemForETH` now support per-leg minimum arrays, but the protocol cannot derive user-specific tolerance on-chain. Frontends/keepers must quote each component route immediately before submit, apply tolerance, and pass arrays aligned to component index. Backward-compatible overloads default these arrays to zero and should not be used for production value-bearing UX.
- **Depth-dependent valueBefore quote.** Subsequent mint issuance uses a full-supply `getAmountsOut` quote for `valueBefore`. This is depth-dependent but symmetric with the redeem quote path, and acceptable only once live feed sanity bounds/per-component route checks are active.
- **Oracle/feed coverage incomplete.** Component feeds can be zero for non-adapter legacy routes, but then NAV/sanity checks are skipped. MAG7 launch should configure all stock/USD feeds and ETH/USD.
- **Market-hours feed policy.** Production `maxFeedAge` is 24h by design. Weekend/holiday mints may revert with `FeedStale(feed, updatedAt, age)` until stock feeds refresh; `redeemForStocks` does not read feeds and remains available.
- **Fee-tier flash gaming accepted.** Fee discounts read current BENTO balance; flash-borrowing BENTO to reduce fees is possible and considered low-severity in Phase 1.
- **Issuer pause/blocklist risk.** Paused component transfers are converted into claims, but blocked engine/vault addresses or broad issuer restrictions could still require operational intervention.
- **TVL caps are essential.** Initial cap should stay small (suggested 25 ETH/box) until route depth, pause behavior, and accounting are battle-tested.
- **Buyback manipulation risk.** FeeCollector rate limits buybacks, but keeper should still compute sane `minBentoOut` off-chain.
- **BENTO fee-on-transfer integration.** BENTO taxes only transfers to/from configured `taxedPair` pools; plain wallet transfers are tax-free. Integrators that move BENTO directly against DEX pairs must account for fee-on-transfer behavior unless they are exempt. Production exemptions should include `BoxEngine`, `FeeCollector`, every `BoxVault`, the LP-seeding wallet, and `0x000000000000000000000000000000000000dEaD`; FeeCollector/DEAD exemption keeps protocol buyback-and-burn untaxed.
- **Registry registrar decision.** The included `BoxRegistry` is immutable-registrar. Pick final registrar/deployment flow carefully; wrong registrar means engine auto-registration can fail and manual registration is required.
